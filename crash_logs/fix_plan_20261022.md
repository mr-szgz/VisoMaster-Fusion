# Overnight Python/Qt crash: investigation and implementation plan

Status: investigation and plan only; application code has not been changed.

## Evidence and confidence

- Windows event 1000 records the portable Python process crashing on October 22, 2026 at 05:38:09 Toronto time. The dump records approximately 9 hours 16 minutes of process uptime.
- The exception is an invalid read at `python312!PyObject_GetAttr+0x16`, with an invalid object pointer in RCX. This establishes native memory failure, not an ordinary Python exception.
- The main-thread stack passes through a queued Qt meta-call, Python, the QtWidgets `setStyleSheet` wrapper, Qt widget palette updates, a QProxyStyle Python callback, and Python attribute lookup.
- Disassembly resolves the wrapper's method-name literal to `setStyleSheet` and the callback's class-name literal to `QProxyStyle`. The callback builds four Python arguments, consistent with `styleHint`; the application's only QProxyStyle override is `ProxyStyle.styleHint`.
- Qt export-only stack labels such as `QPlainTextEdit::tr+large-offset` are not reliable identification of the specific widget. The dump does not establish which Python caller initiated the stylesheet change.
- The portable runtime currently contains PySide6 6.11.0. Python heap/frame memory needed for an exact Python traceback is absent from this minidump. The code or extension that originally invalidated the pointer remains unproven.

## Relevant execution paths

1. `main.py:76` installs `ProxyStyle()` application-wide. `app/ui/core/proxy_style.py:10` handles one slider hint but also intercepts style hints for every other widget. Its global re-entry flag and exception handler substitute zero for some native results. These do not protect against an access violation.
2. `app/processors/video_utils/media_pipeline.py:1040` starts the VRAM timer at five-second intervals. It emits a memory update, eventually reaching `common_actions.set_gpu_memory_progressbar_value` at line 579. That function can call `QProgressBar.setStyleSheet` when its computed style changes. It already caches styles; this is not an unconditional five-second stylesheet rewrite.
3. `job_manager_actions._load_job_controls_and_state` calls `common_actions.set_control_widgets_values`, which executes control callbacks even for unchanged values. `ThemeSelection` invokes `control_actions.change_theme`, which unconditionally reapplies the application's stylesheet. This is a second route through styling during batch transitions; it is not proven to be the caller in the dump.
4. `job_manager_actions.py:2790` and `:2813` directly call `video_processor.stop_processing()` from `_trigger_and_wait_for_processing`, executed in `JobProcessor.run()`. `stop_processing` stops GUI-owned timers and resets UI controls. This is a concrete thread-affinity defect, although there is no evidence that the watchdog fired in this crash.

## Probes completed

- An isolated process using the portable runtime, actual ProxyStyle, application's dark QSS, and the actual VRAM-update function completed 10,000 alternating normal/high-memory stylesheet updates with event processing and periodic garbage collection. No crash reproduced. The test used Qt's offscreen platform and did not run GPU inference.
- An isolated worker-thread signal probe using the application's decorated free-function-plus-partial connection pattern delivered its callback on the GUI thread on this runtime. Do not claim that the existing VRAM partial connection caused an off-thread update.
- At investigation time, uncommitted edits included job-management files and their tests. Those changes are now committed; implementation must preserve and integrate with them.

## Concrete implementation sequence

### 1. Remove the global Python style callback

- Remove the ProxyStyle import and `app.setStyle(ProxyStyle())` from `main.py`. Keep the native default style and existing QSS/theme selection.
- Replace the single behavior it provides—left-click absolute slider positioning—with local mouse handling for the affected sliders. ParameterSlider and ParameterDecimalSlider already implement click positioning; reconcile their subsequent base mouse handler so clicks do not also page-step.
- Cover the active TimelineSeekSlider, timelineZoomSlider, targetVideosWidthSlider, and targetVideosHeightSlider. Put behavior in existing slider classes/event-filter wiring, rather than editing the generated Designer file by hand. Preserve drag state, tracking, sliderPressed/sliderMoved/sliderReleased, keyboard/wheel behavior, orientation, inverted appearance, range, and decimal step semantics. Use QStyleOptionSlider geometry and sliderValueFromPosition for the handle/groove mapping.
- Remove the obsolete proxy implementation once its runtime and test references are removed. Do not replace the re-entry guard with another guard, catch, or fallback value.
- This removes the observed global callback path. It is not proof that the original memory-corruption source has been eliminated.

### 2. Eliminate redundant application-wide theme reapplication

- Track the successfully applied theme at startup, then make `change_theme` apply QSS only when the requested theme differs. Update the tracked value after applying the stylesheet.
- Preserve theme changes explicitly requested by a job or user and the existing VRAM-color refresh on an actual theme change.
- Do not globally skip other unchanged control callbacks; some have necessary job-loading side effects. Keep the existing VRAM style cache.

### 3. Correct worker-thread shutdown

- Replace the two direct stop calls in the watchdog/wait paths with the existing `QMetaObject.invokeMethod(self, "stop_job_recording", Qt.QueuedConnection)` mechanism already used for the start timeout.
- Keep the current failed-job result and stop behavior; do not add retries, restart processing, or mask errors.
- Verify the queued stop completes before batch-completion restoration or processor disposal. Exercise the existing `run_ui_operation`/completion-defer mechanism under this ordering; keep the JobProcessor alive through delivery. If that mechanism does not establish ordering, explicitly signal stop completion before restoration rather than blocking the GUI thread.
- The QThread object is created on the GUI thread; its `run()` executes on the worker. Its existing decorated stop slot therefore belongs to the GUI thread. Correct the misleading ownership comment rather than moving the QThread object to itself.

## Required validation before calling this resolved

1. Real-Qt subprocess tests on the portable runtime: slider click, drag, release, keyboard and wheel behavior; integer/decimal stepping; timeline seeking and zoom/card-size sliders. No mocked style objects.
2. Same-theme job transitions must not call QApplication.setStyleSheet again; actual theme changes must apply once and refresh the VRAM colors.
3. Worker-emitted watchdog shutdown must execute stop_processing on QApplication.thread(), before batch restoration, with no timer/thread warnings. Keep this test independent of GPU work.
4. Repeat the 10,000-update styling probe after the changes, plus repeated batch/dialog creation and teardown. Run Windows-platform tests as well as offscreen tests.
5. Run the existing job-processing, completion, progress-dialog and slider tests affected by the patch. Preserve the current unrelated working-tree changes.
6. Perform a supervised 12-hour-or-longer representative GPU batch on the same portable installation. Check output completion, process survival, memory trend, and Windows crash events. The earlier CUDA-driver crash has a different signature and is not resolved by a Qt-only patch.

If a native crash recurs, retain a dump with Python heap memory and a fatal Python stack trace to distinguish residual memory corruption from the removed callback path. No recovery/fallback implementation is part of this plan.
